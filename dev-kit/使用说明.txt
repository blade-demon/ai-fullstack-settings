团队开发环境安装、配置与卸载（macOS）

成员唯一入口为 devtool-helper.sh。连接团队内网，下载维护者提供的文件，
在终端进入下载目录，运行：bash devtool-helper.sh
无需克隆仓库、填写服务器地址或预装 Python、Node、Go、Homebrew。
本文是仓库说明，不放入成员临时工具包；.sh 以终端运行为准，不承诺双击。

一、安装与配置

首页有“安装与配置”“卸载工具”“一键安装配置全部”。
安装页方向键移动，空格勾选，左右键切换版本，Enter 直接预检并安装已选项。
当前页显示版本、目录、依赖和默认配置影响；空选择不执行。
预检失败保留选择并显示原因，调整后再次按 Enter；没有额外安装确认页。

六类组件为 JDK、Gradle、nvm、IDEA、iTerm2、Oh My Zsh。
全量默认：JDK 8、Gradle 4.5.1、nvm 0.40.8 与 Node 14.21.3、
iTerm2 3.7.3、Oh My Zsh 与四个插件、IDEA 2025.3.6.1 与六个插件。
执行顺序：JDK → Gradle → nvm/Node → iTerm2 → Oh My Zsh → IDEA/插件。
只选部分组件也遵循此顺序；Gradle 自动补入 JDK 8 依赖。
IDEA 单独安装不隐式安装 JDK，没有可用 JDK 时需另行配置 SDK。

Gradle 可选 4.5.1、6.8 或 all（两版）。单版成为新终端默认；
两版同装保留有效默认，无有效默认时用 4.5.1，不由安装顺序决定默认。
Node 固定为 10.24.1、14.21.3、18.20.8、22.23.3。
安装页、一键全部及未指定 Node 版本的安装默认选择并安装 Node 14.21.3。
Node none 只安装/配置 nvm，不下载 Node，不改 default；显式选择 all 才安装四版，
首次或旧 default 失效时回退到 14，已有有效 default 保留（包括历史 Node 16）。
单版成为默认，默认单版 14 同样遵循此规则。
Node 16 不再提供新安装，不自动删除既有版本。
Node 10、14 使用官方 x64 包；Apple Silicon 需已有 Rosetta，工具不自动安装
Rosetta、不回退源码编译。Node 18、22 按本机架构选择。
iTerm2 要求 macOS 13+；Oh My Zsh 要求已有可用 Git，不自动安装系统开发工具。
保存工作并正常退出 IDEA 后再安装插件或修改 SDK 登记。

界面显示总组件进度和当前阶段；下载完成不等于安装、配置和验证完成。
失败任务及依赖跳过、取消和需处理项会分别显示；独立任务可继续，取消停止后续任务。
已经成功安装的内容保留，不自动回滚。成员流程不选择业务项目、不执行构建。

二、安装后的版本切换

结果页和报告列出实际成功版本、默认值、实际加载路径及可复制切换命令。
helper/TUI 是子进程，不能替父终端切换环境。新开终端即可加载配置；
要在原终端立即使用，执行结果中的加载命令。下面仅为默认路径示例，
自定义路径以实际输出为准，未安装的版本不能直接切换。

  source "$HOME/.config/java-dev/env.sh"
  gradle_use --list
  gradle_use 4.5.1            # 当前终端
  gradle_use 6.8 --default    # 当前终端并设置新终端默认
  gradle --version

  export NVM_DIR="$HOME/.nvm"
  . "$NVM_DIR/nvm.sh"
  nvm ls
  nvm use 22                 # 当前终端
  nvm alias default 14       # 设置新终端默认，当前终端仍需切换
  nvm use default
  node -v
  npm -v

只安装 nvm 时，本次未安装 Node；结果按已有状态显示 nvm ls 和默认值。
Gradle 函数长期保存在受管环境中，nvm 是 Node 唯一切换方式；
切换无需联网、重装或保留下载临时目录，不修改业务项目 Wrapper 或 IDEA 分发设置。

三、卸载

运行 bash devtool-helper.sh uninstall，进入默认全不选的六组件卸载页。
选择组件和具体实例，核对路径、配置影响、保留项和阻断原因，输入 DELETE 后才执行。
卸载只静态扫描，不启动待删 SDK，也不把未选组件附带删除。
IDEA 可以保留用户配置、SDK 登记及插件；只有与所选应用明确关联的数据可清理。
JDK/Gradle 必须有有效工具来源标记；nvm/Node、Oh My Zsh/插件需要可信来源和快照，
外部版本、未知或用户新增修改的内容保留。Node 全局包影响会在计划中列出。
iTerm2 需要绑定应用的可信收据，偏好、历史和会话保留；
不自动退出正在运行的 iTerm2，若它是当前终端宿主，请从其他终端重试。
业务项目、Gradle 用户配置和缓存、系统 zsh/Git/开发工具不删除。

清理永久删除所选范围，不建立配置或软件备份，不自动回滚。
实际执行记录写入 ~/Library/Logs/team-java-env/cleanup/；只读预览和确认前取消不写记录。
删除后新开终端检查；原终端可能仍保留旧变量。

四、CLI、帮助与日志

  bash devtool-helper.sh help
  bash devtool-helper.sh help install
  bash devtool-helper.sh --dry-run install --components all
  bash devtool-helper.sh install --components nvm --node-version none
  bash devtool-helper.sh install --components gradle --gradle-version all --dry-run
  bash devtool-helper.sh uninstall --components nvm,iterm2,oh-my-zsh --dry-run

help / help install / help uninstall：本地帮助，不联网。
动作前全局 --dry-run：只显示下载地址和转发参数，不联网。
动作后 --help / --dry-run：下载最新工具后显示业务帮助或只读计划，不安装、不删除。
无交互终端的实际安装必须明确 --components；非交互真删须明确组件加 --apply --yes。
frontend、--frontend、--plain、两份旧 .command 和数字菜单均已移除。

安装记录：~/Library/Logs/team-java-env/components/<本次记录>/
含计划、组件日志、阶段和最终状态；TUI 完整日志在同一根目录的 tui/。
底层 Java 修复 history/ 历史及已有备份继续保留，不因入口迁移删除。
失败后查看实际退出码与日志；分享前检查密码、令牌和私有配置。
Esc 取消并等待当前任务退出，Ctrl+C 取消后退出；结果页 Enter/Esc 返回。
界面缺失或校验失败时重新下载，不退回旧文本菜单。

五、安装后仍需完成

IDEA/iTerm2 安装在当前用户 $HOME/Applications，不是系统 /Applications。
在 IDEA 手动导入业务项目，确认 Project SDK、Gradle JVM、Wrapper/LOCAL 分发，
执行 Gradle 同步并验证插件实际功能。业务构建由维护者明确指定项目另行验证。
安装包齐全不代表业务依赖、数据库驱动或 MySQL 镜像已就绪。
无 Node 的成员继续用 Shell helper；已有 Node >=14.14/npm 可用团队本地 npx 薄入口。
详细指南见仓库 README.md、docs/environment/ 与 docs/distribution.md。
