# IDEA 卸载交互流程

**用户要求：** 直接执行卸载入口时提示是否删除 IDEA；确认后关闭 IDEA，再删除软件。继续完成此前 SDK 登记与项目引用名称统一。

**设计：** 真实交互终端进入清理引导；非交互默认与显式 `--dry-run` 保持只读。先展示识别到的 IDEA 应用路径并选择范围，最后展示完整计划，输入 `DELETE` 确认后才请求正常退出 IDEA。退出失败、取消保存或超时停止全部删除。退出成功后重扫、校验计划，再执行现有清理逻辑。

- 默认交互选择只删除 IDEA 软件，保留配置和用户插件。
- 新增 `--include-idea-apps` 明确选择软件范围；既有 `--include-idea` 保持完整 IDEA 应用、配置和插件范围。
- 保持 `--include-system` 的系统路径保护和 `--apply --yes` 的显式自动化授权。
- 使用应用标识和运行进程定位 IDEA；不启动未运行应用，不强制结束进程，不影响其他 JetBrains 软件。
- 开发测试只使用临时应用和配置，不关闭或删除本机 IDEA。

## 验证结果

清理相关 86 项测试、完整隔离回归 373 项全部通过。独立复核验证了内部 JBR 与无法归属的 IDEA 进程均不会漏过删除保护。Python 3.8 AST、Bash 入口语法与差异格式检查通过。正常退出请求使用可控替身测试，未执行本机 IDEA 退出或卸载。
